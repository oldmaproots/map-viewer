# 地図ビューア（04MapViewer）

全国Q地図のような地図タイル切り替えサイトを自作するプロジェクト。
地理院地図・Q地図風の左サイドパネルでレイヤーを選ぶ構成。
家系図プロジェクト（01FamilyTree）とは無関係の独立プロジェクト。

**公開URL: https://oldmaproots.github.io/map-viewer/** （GitHub Pages。リポジトリ: oldmaproots/map-viewer）

## 動かし方

- `python serve.py` で http://localhost:5504 に配信される（キャッシュ無効化つき）。
- 01FamilyTree の `.claude/launch.json` に `map-viewer-server` として登録済み。

## ファイル構成（ビルド不要）

| ファイル | 役割 |
|---|---|
| `index.html` | 画面の骨組み。Leaflet / MapLibre GL をCDNから読み込む |
| `style.css` | 左パネルなどの見た目 |
| `script.js` | 本体。サイドパネル生成・レイヤー管理・背景地図 |
| `konjaku-data.js` | 今昔マップ全313レイヤーの一覧（**自動生成。手で編集しない**） |
| `dem-layers.js` | 数値標高タイルを読んでブラウザ内で地形を描く部品 |
| `timeseries.js` | 年代別写真の時系列スライダー |
| `kumamoto.js` | 都市計画図（熊本県）のGeoJSONレイヤー定義 |
| `moj-style-2026-*.json` | 法務局地図のMapLibreスタイル（Q地図の定義を複製） |
| `data/kumamoto/` | 都市計画GeoJSON（`scripts/build_kumamoto_data.py`が生成） |

   タイル: `ktgis.net/kjmapw/kjtilemap/{地域}/{時期}/{z}/{x}/{-y}.png`（`{-y}`=Y反転のTMS方式）。
   出典表示必須: 「今昔マップ on the web」((C)谷謙二)
2. **公図・地番図・地名** — 2026年 法務局地図（登記所備付地図）【KotobaMedia】。
   ベクトルタイル `tiles.kmproj.com/mojxml/2026.json` をMapLibre GL(+leaflet-maplibre-gl)で描画。
   ズーム16以上で筆界と地番文字。塗りつぶしなし版もあり。
3. **地形** — 基盤地図情報(標高) DEM1A【Q地図タイル】/ DEM5A【地理院】。
   数値標高タイル（標高=(R×65536+G×256+B)×0.01m、2^23=無効値）をcanvasで解読し、
   赤色立体風・陰影起伏・傾斜量を**ブラウザ内で計算**（`dem-layers.js`）。
   タイルがないズームでは上位ズームから切り出して拡大（オーバーズーム）。
   DEM1A: `qchizu3.xsrv.jp/mapdata/d52001/{z}/{x}/{y}.webp`（512px, 〜z16）
   出典表示: Q地図タイル(測量法に基づく国土地理院長承認(使用)R7JHs10)
4. **年代別の写真** — 時系列表示（ZL14以上）。1928年頃〜最新の28年代

   画面中央のタイルを各年代で試し読みし、写真がある年代を緑の点で表示。
5. **標高・土地の凹凸** — 色別標高図（地理院reliefタイル）と、
   自分で作る色別標高図（最低/最高標高・段数・陰影・データ元を指定してブラウザ内で描く）。
6. **都市計画図 > 熊本県** — **都市計画決定GISデータ（国土交通省）令和7年度**のGeoJSON14種。
   （2026-08-01に国土数値情報A55・令和6年度版から差し替え。準都市計画区域が新規に加わった）
   **用途地域の色は熊本県の都市計画総括図の公式凡例に準拠**（`kumamoto.js`の`YOUTO_CHIIKI_FILL`）。
   建ぺい率・容積率つきの凡例表（`_reference/用途地域凡例_色見本.png`）の色見本を
   1マスずつ実測したRGBをそのまま使い、
   凡例の並び順も公式凡例と同じ（住居系→商業系→工業系）。境界線は塗りつぶし色を暗くして自動生成。
   田園住居地域だけはこの凡例表に載っていない（熊本県内に指定がない）ため、
   国の計画図凡例（`_reference/用途地域凡例.pdf`）の「うすい茶」を将来のために残している。
   **用途地域以外の色・表現も公式総括図の凡例（2ページ目左の【総括図凡例】）から実測して合わせた**：
   - 防火地域＝灰紫／準防火地域＝桃／風致地区＝緑／特定用途制限地域＝橙／地区計画＝茶 の
     **斜線ハッチ**（`KUMAMOTO_CATEGORY_COLORS`と各レイヤー定義の`hatch:true`）。
   - **斜線は「縁だけ」に描く**（中は塗らず背景地図が見える）。これが県の総括図の描き方で、
     用途地域などに重ねても下が読める。帯の幅は画面上で12px固定（`HATCH_BAND_WIDTH`）。
   - **斜線の向きはレイヤーごとに違う**（`hatchDir`）。凡例PDFの見本から実測した結果:
     防火地域・準防火地域・風致地区＝**右下がり`\`**／特定用途制限地域・地区計画＝**右上がり`/`**。
     （臨港地区も右上がりだが、元データに該当データがなくサイトには無い）
   - 特別用途地区＝**色付きの点線の枠**（大規模集客施設制限＝黄緑／特別工業＝金／文教＝青／
     娯楽レクリエーション＝赤／行政・文化拠点＝紫）、公園・緑地・墓園＝**緑の枠線**（`frameOnly:true`）。
   - 都市計画区域の境界＝**黒の一点鎖線**（準都市計画区域は二点鎖線）、
     都市計画道路＝**黒い線**。
     - 元データは**市町村ごとに分かれている**ため、そのまま描くと都市計画区域の中に
       市町村の境目の線が入り、外枠と区別できない。区域名の欄（`TokeiName`）も
       119件中59件が空欄で名前ではまとめられない。
       そこで`scripts/build_toshikeikaku_frame.py`が**市町村名から17の都市計画区域に
       振り分けて大枠にまとめ直す**（熊本都市計画区域＝熊本市・合志市・菊陽町・益城町・
       嘉島町の5市町。天草市だけは旧本渡市と旧牛深市で2区域に分かれるため緯度で振り分け）。
     - **隣り合う区域の境界で一点鎖線が汚くならないようにしてある**。
       一点鎖線は線の始まりから点と線を並べるので、同じ場所に2本引くと点の位置がずれて
       つぶれてしまう。そこで**共有している境界はまったく同じ座標の線を区域の数だけ**
       用意している。同じ座標なら点の位置もそろうので重ねてもきれいに見え、
       片方の区域を非表示にしてももう片方が残るので境界が消えない。
     - さらに元データは隣どうしの境界の座標がそろっていない（熊本と菊池は約19km
       隣り合うがぴったり一致は0m、重なり面積9.1ha）。そのため線を作る前に
       **すき間と重なりを25mまで掃除して境界を1本にそろえている**。
       この掃除で面積が変わるのは最大でも0.5%（牛深+0.42%／長洲-0.49%）。
     - 出力は`toshikeikaku_kuiki_line.geojson`（枠線・93件）と
       `toshikeikaku_kuiki_area.geojson`（面・17件）。地図に描くのは線のほうで、
       面はクリックしたときの区域名の判定に使う（線には内と外が無いため）。
       レイヤー定義の`clickFile`/`clickCategoryFields`がその仕組み。
   - **区域区分は公式凡例に合わせて5区分**（`kumamoto.js`の`KUIKI_KUBUN_FILL`）。
     市街化区域＝濃い桃／市街化調整区域＝淡い桃／用途指定区域＝茶／用途指定区域外＝薄い茶／
     全域用途未指定区域＝薄い紫。色は凡例の色見本から実測した値。
     - 元データにあるのは**市街化区域と市街化調整区域だけ**。残り3区分は
       `scripts/build_kuiki_kubun5.py`が都市計画区域・用途地域・区域区分を重ね合わせて計算する。
       線引きしていない都市計画区域を用途地域の有無で分け、用途地域が1つも無い
       都市計画区域を「全域用途未指定区域」とする。出力は`data/kumamoto/kuiki_kubun5.geojson`。
     - 「全域用途未指定区域」の判定には**17区域にまとめた面**
       （`toshikeikaku_kuiki_area.geojson`）を使う。都市計画区域まるごとで見る区分なので、
       市町村ごとに分かれた元データで判定すると誤る。ただし図形の引き算そのものは
       元データで行う（まとめ直した面はすき間を埋めてあるぶん形が違い、
       引き算すると細長いくずが1,700個以上に増えてしまうため）。
     - 図形の引き算では境界のずれから細長いくずが大量にできる（実際に717個できた）。
       100平方メートル未満は捨てている（失う面積は全体の0.0002%）。
     - 検証: 5区分の合計面積が都市計画区域と**0.001%の差**で一致し、区域外へのはみ出しは0。
     - **QGIS版（09QGISCityPlanning）も同じファイルを使う**ので、両者で塗り分けがそろう。
   - **立地適正化計画区域・高度利用地区・土地区画整理事業は
     公式凡例に載っていないため、根拠のない色を付けず従来の色のまま残している**。
   - 斜線ハッチは**Canvas描画のまま**（大きなデータでも軽くするため。SVGにはしない）実現している。
     `L.Canvas`を継承した`HatchCanvas`で塗り処理`_fillStroke`だけ差し替えている。
     縁だけに描く仕組みは「`ctx.clip()`で図形の内側だけを描画対象にし、輪郭を帯幅の2倍の
     太い線でなぞる」というもの。線の外半分はclipで消え、内側にだけ帯が残る。
     穴あきの図形にも効き（`evenodd`）、帯より細い小さな区域は全体が斜線になって消えない。
     斜線タイル（8×8）とパターンは「色＋向き」ごとにキャッシュしている。
   - 凡例の色見本も地図と同じ**枠状**にしている。CSSの`mask`で中をくり抜く方式で、
     斜線の角度は`45deg`＝右下がり、`-45deg`＝右上がり（CSSはグラデーションの軸と縞が
     直角の関係なので、指定角度と見た目が逆になる。ブラウザ上で実測して確認済み）。
   **容積率・建ぺい率の丸印**（用途地域の下のチェック）＝都市計画図の決まりどおり、
   円を三分割して上から「容積率／用途地域の略称／建ぺい率」を書く（`youto-circles.js`）。
   - 丸を置く点は`scripts/build_kumamoto_data.py`が先に計算して
     `data/kumamoto/youto_circles.geojson`に入れてある（区域の中で境界からいちばん離れた点）。
     **QGIS版（09QGISCityPlanning）も同じファイルを使う**ので、両者で同じ位置に丸が出る。
   - **ズーム15以上**で表示。それ未満だと重なって読めない（画面内720個→ズーム15で約45個）。
   - 丸より小さい区域には出さない（区域からはみ出さないように）。
   - 丸を出さない区域が2種類ある（公式凡例の決まり）。
     容積率・建ぺい率が空の区域と、**第１種住居・第２種住居・準住居・準工業・工業地域の200/60**
     （凡例に「○の表示のない地域は総て200/60です」とあるため省略）。720件が対象になる。
   - 円の大きさと文字の大きさは、**3桁の容積率が円からはみ出さない**ように決めてある。
     変えるときは実データに出る全組み合わせで、はみ出さないか確かめること。
   - **三分割の線は端が円周に接する**。中段の幅を100%にして、はみ出した分を
     親の`overflow:hidden`＋`border-radius:50%`が円の形に切り取っている
     （幅を狭めて短い線にする方式だと、円に届かず浮いて見える）。
   - 丸印は**常に「選択中のレイヤー」一覧の先頭に入る**（`buildLayerRow`の`alwaysOnTop`）。
     用途地域の色の下に潜ると文字が読めなくなるため。▲▼で後から動かすことはできる。
   表示中に地図をクリックすると、当たった区域の**元データの項目をすべて**表にして出す
   （決定年月日・容積率・建ぺい率・市町村など）。項目名の日本語訳は
   `kumamoto.js`の`KUMAMOTO_FIELD_LABELS`。訳の無い項目は元データの名前のまま出す。
   **右下に凡例**が出る（チェック中のレイヤーのみ・折り畳み可・項目ごとに地図上の表示/非表示を切替）。
   用途地域の凡例の下には**公式凡例の「注)」をそのまま載せている**
   （`kumamoto.js`の`YOUTO_LEGEND_NOTES`）。文中の`{丸:200/60}`という書き方が、
   容積率(上)と建ぺい率(下)を書いた小さな丸印に置き換わる（`buildLegendNoteBody()`）。
   丸印の読み方と、表示されるズームの説明もここに置いてある
   （以前は左パネルの説明文だったが、凡例にまとめた）。
   凡例の仕組みは`kumamoto.js`の`initKumamotoLegend()`。非表示は該当項目を透明で描く方式
   （`def._hiddenItems`）で、クリック判定`kumamotoMatchesAt()`も非表示項目を無視する。
7. **背景地図** — 標準/淡色/白地図/空中写真（地理院）＋Googleマップ/Google航空写真。
   Googleは公式API＋GoogleMutantプラグインで表示（02都市計画マップとAPIキーを共用）。
   キーはリファラー制限付き: **公開サイト(oldmaproots.github.io)では動くが、
   ローカル(localhost:5504)は制限に含まれておらず灰色になる**。ローカルでも使いたければ
   Google Cloud Consoleでキーのリファラーに `http://localhost:5504/*` を追加する。
   読み込み失敗時は選択肢自体が出ない／標準地図に戻るフォールバックあり。
   さらに **「基盤地図情報(線)」** を追加（`fgd-basemap-style.json`）。
   国土地理院の基盤地図情報（基本項目）から海岸線・行政界線・道路縁・水涯線・
   建築物外周線など**9項目の線だけ**を取り出し、灰色一色で描く白地図に近い下地。
   都市計画図を重ねて見るのに向いている。
   - 実体は**ベクトルタイル**（68.8MB・ズーム8〜14・3,504タイル）。
     元は1.5GBのGeoPackageだが、タイルにすると画面に映っている範囲の
     必要な分だけを読むので軽い。作り方は`10FGDBaseMap/scripts/build_web_tiles.py`。
   - **タイルはこのリポジトリには入っていない。**
     配信専用の別リポジトリ [oldmaproots/map-tiles](https://github.com/oldmaproots/map-tiles)
     に置き、`pmtiles://https://oldmaproots.github.io/map-tiles/fgd_lines.pmtiles`
     として読んでいる。
     同梱していたときはサイト全体が約110MBになり、
     **GitHub Pagesの配信が10分の制限時間に間に合わず失敗した**
     （`Current status: deployment_queued`の繰り返し→`Timeout reached, aborting!`。
     ビルド自体は33秒で成功していた）。
   - PMTilesは1つの大きなファイルの**必要な部分だけを取ってくる**方式
     （HTTPの範囲リクエスト）。GitHub Pagesは範囲リクエストにもCORSにも対応しているので、
     別ドメインに置いても読める。
     `index.html`で読み込む`pmtiles`が`pmtiles://`の読み方をMapLibreに教えている。
   - **`serve.py`（ローカル確認用サーバー）にも範囲リクエスト対応を足した**。
     Python標準のサーバーは対応しておらず、
     「supports HTTP Byte Serving」というエラーで表示できなかったため。
   - **白の背景レイヤーを1枚敷いている**（スタイルの`fgd-haikei`）。
     線しか描かないレイヤーなので、これが無いとLeaflet本体の既定の背景色（`#ddd`の灰色）が
     透けて見えてしまう。ここだけ白にしたいので、`style.css`ではなくスタイル側で敷いている。
   - 引くと海岸線と行政界線だけ、拡大すると道路や建物が出る（建築物はズーム14以上）。
     背景地図なので`base-vector`という専用ペイン（z-index 210）に描き、
     都市計画図などの重ねるレイヤーより奥になるようにしている。

そのほかの機能:
- **前回の状態を覚えている**（リロードしても消えない）。
  - 見ていた場所と縮尺 … localStorageの`map-viewer-last-view`
  - 選んでいたレイヤー・重ね順・透過・隠しているか・背景地図の種類 …
    `map-viewer-layers`（`saveLayerState()` / `restoreLayerState()`）
  - **初めて開いたときは** 背景地図＝基盤地図情報(線)、
    レイヤー＝用途地域＋容積率建ぺい率（`DEFAULT_LAYER_STATE`）。
  - 復元はカテゴリを全部作り終えたあとに1回だけ行う（script.jsの末尾）。
    レイヤーの読み込みは非同期なので、`buildLayerRow`のチェック処理を
    `applyCheck()`として取り出し、1つずつ`await`しながら上の行から順に足していく。
    こうすると保存したときの重ね順がそのまま再現される。
    「いちばん手前に置く」レイヤー（丸印）は足すと先頭へ入るので、最後に並べ直す。
- **住所・地名検索**（右上）— 国土地理院の住所検索API（無料・キー不要）。02プロジェクトv2と同方式。
  - **虫眼鏡は左、✕（消す）は右**。✕を押すと入力・検索結果・**地図上のピンをまとめて消す**。
  - **何も入れずに検索してもピンが消える**。
  - 消すものが何も無いときは✕を隠す（`refreshSearchClearButton()`）。
- **現在地ボタン**（右下）— ブラウザの位置情報APIで現在地＋誤差円を表示。

## 共通の仕組み

- レイヤーをONにすると**左パネル下部**の「選択中のレイヤー」に載り、
  透過スライダー・重ね順の▲▼・✕（削除）が使える。`registerActiveLayer()`（script.js）。
  - 「選択中のレイヤー」は**下部の独立したスクロール領域**（`max-height:40%`）に置いてあり、
    項目が増えても上のカテゴリ一覧（チェックボックス）は動かない。地理院地図・Q地図と同じ配置。
  - **重ね順の変更（▲▼）**：レイヤー1つにつき専用の`pane`を`map.createPane()`で作り、
    一覧の並び順から`pane.style.zIndex`を割り当てる（`applyLayerOrder()`）。
    **一覧の上にあるものほど地図で手前**（地理院地図と同じ向き）。タイル・ベクトルタイル(法務局)・
    Canvas描画のGeoJSON(都市計画図)・自作DEM・年代別写真の**すべての種類**に対応。
    GeoJSONはレイヤーごとに専用のCanvasレンダラー（`createKumamotoRenderer()`）を持たせている。
  - 透過スライダーは種類ごとの差を吸収するため、**レイヤー専用paneの不透明度**で一括調整する。
    **一番右＝完全に不透明**。塗りつぶし自体は`fillOpacity:1`（不透明）にしておき、
    「ちょうどよい濃さ」はレイヤー定義の`defaultOpacity`（＝スライダーの初期位置）で作る。
    例: 用途地域は70%から始まるので、右へ動かせば公式凡例の色そのままの濃さにできる。
    線だけ・枠だけのレイヤーは薄める必要がないので`defaultOpacity:1`。
  - スライダーの右に**表示/非表示ボタン（👁）**がある。一覧から外す✕とは別で、
    透過や重ね順の設定を保ったまま地図の表示だけを消せる。
    CSSで隠すのではなく`map.removeLayer()`で本当に外すので、
    クリックしたときのポップアップにも隠したレイヤーは出てこない。
- **⚙設定ボタン**（左パネル右上）で都市計画図の色を変えられる。
  - 変えた色はlocalStorage（キー: `map-viewer-kumamoto-colors`）に保存され、次に開いても残る。
  - 地図と凡例の色は必ず`resolveKumamotoColors()`（kumamoto.js）を通す。
    利用者が変えた色があればそれを、無ければ公式凡例の色を返す一本道にしてある。
    塗り色を変えると枠線は自動でその色を暗くしたものになる。
  - 項目ごとの「戻す」と、全部まとめて公式凡例に戻すボタンの両方がある。
  - 種別の一覧はGeoJSONを読んで初めて分かるため、**表示中のレイヤーだけ**が設定画面に並ぶ。
- 各カテゴリは`<details>`要素のアコーディオン。`buildCategory()`/`buildLayerRow()`が共通部品。
- 表示位置はlocalStorage（キー: `map-viewer-last-view`）に保存。初期表示は熊本周辺。

## 都市計画データの更新手順

1. [都市計画情報 全国データダウンロードページ](https://www.mlit.go.jp/toshi/tosiko/toshi_tosiko_tk_000087.html)
   から熊本県の**GeoJSON形式**をダウンロードして展開する
   - シェープファイル形式でも同じ内容だが、GeoJSONなら変換ライブラリ（GDAL）が要らない
   - **CityGML形式は使わない**。都市計画道路が丸ごと欠けている（93ファイルしかない）
2. 展開したフォルダを `_source/R7_都市計画決定GISデータ_熊本県_GeoJSON/` に置く（Git管理外）
3. `python scripts/build_kumamoto_data.py` を実行する
   - 市町村ごとに分かれたファイルを種類ごとに1つへまとめ、座標を6桁に丸め、空の属性を削る
   - この軽量化で通信量が約半分になる（8.0MB→3.4MB。GitHub Pagesのgzip後で比較）
4. 表示される件数が想定どおりか確認し、commit & push

サイト側（`kumamoto.js`）の変更は、**レイヤーの種類が増えないかぎり不要**。
元データの属性名（`YoutoName`・`AreaType`・`DistName`・`ParkType`）は国土数値情報と同じなので、
色分けや凡例はそのまま動く。
